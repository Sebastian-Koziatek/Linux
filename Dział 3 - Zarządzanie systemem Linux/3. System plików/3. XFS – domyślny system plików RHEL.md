# XFS – domyślny system plików RHEL

> **W tej lekcji:** dowiesz się, dlaczego Red Hat wybrał XFS, co XFS robi lepiej od ext4, czego nie potrafi (zmniejszanie) i jak go założyć, powiększyć, sprawdzić i opisać etykietą.

XFS to domyślny system plików RHEL, Rocky i AlmaLinux – po instalacji z domyślnymi ustawieniami `/` i `/boot` leżą właśnie na nim, więc naprawa po awarii dysku i powiększanie wolumenów będą na tych systemach dotyczyły XFS. Narzędzia nazywają się inaczej niż dla ext (`xfs_repair` zamiast `fsck`, `xfs_growfs` zamiast `resize2fs`), a XFS ma też jedno istotne ograniczenie: nie da się go zmniejszyć.

## Jak to działa

XFS powstał w firmie SGI w 1994 roku dla systemu IRIX, czyli dla stacji graficznych i serwerów przetwarzających ogromne pliki wideo i dane naukowe. Do Linuksa trafił w 2001 roku. Od początku projektowano go pod **duże** – duże dyski, duże pliki, dużo równoległych operacji. Red Hat uczynił go domyślnym w RHEL 7 (2014) i nie zmienił tej decyzji w RHEL 8, 9 ani 10.

Co XFS robi dobrze:

- **Skaluje się.** Partycja dzieli się na **grupy alokacji** (ang. allocation groups), z których każda ma własne liczniki wolnego miejsca i własne i-węzły. Kilka procesów może zapisywać równolegle w różnych grupach bez czekania na siebie. Red Hat wspiera XFS do 1 PiB (1024 TiB) na jednym systemie plików.
- **Dynamiczne i-węzły.** XFS tworzy i-węzły w miarę potrzeb, więc problem „brak i-węzłów mimo wolnego miejsca” praktycznie tu nie występuje.
- **Ekstenty i opóźniona alokacja** – jak w ext4, tylko XFS miał je kilkanaście lat wcześniej.
- **Dziennik metadanych** z sumami kontrolnymi (od wersji 5 formatu, domyślnej w RHEL 7+).
- **Narzędzia dla administratora:** `xfsdump`/`xfsrestore` do kopii zapasowych, `xfs_quota` do limitów na katalog (ang. project quota), `xfs_fsr` do defragmentacji w locie.

Czego XFS nie potrafi:

- **Zmniejszyć się.** System plików XFS można tylko powiększyć. Jeśli przydzieliłeś 500 GB, a potrzebujesz 100 GB gdzie indziej – jedyna droga to kopia danych, usunięcie i założenie od nowa. To główny powód, by planować rozmiary z zapasem i używać LVM: wolne miejsce zostawiasz w grupie woluminów, a nie „na wyrost” w XFS.
- **Działać na bardzo małych partycjach** – poniżej ~300 MB `mkfs.xfs` odmówi. Dlatego małe `/boot` bywa na ext4.

> **Na Ubuntu/Debianie:** XFS jest dostępny (pakiet `xfsprogs`), ale domyślny jest ext4. Polecenia z tej lekcji działają tak samo.

## W praktyce

```bash
# tworzymy XFS z etykietą na partycji ćwiczeniowej (kasuje jej zawartość!)
sudo mkfs.xfs -L dane /dev/sdb1
```

```text
meta-data=/dev/sdb1   isize=512    agcount=4, agsize=327680 blks
         =            sectsz=512   attr=2, projid32bit=1
         =            crc=1        finobt=1, sparse=1, rmapbt=0
data     =            bsize=4096   blocks=1310720, imaxpct=25
naming   =version 2   bsize=4096   ascii-ci=0, ftype=1
log      =internal log bsize=4096  blocks=16384, version=2
realtime =none        extsz=4096   blocks=0, rtextents=0
```

`agcount=4` to liczba grup alokacji, `crc=1` – sumy kontrolne metadanych, `log =internal` – dziennik w tej samej partycji. Jeśli partycja miała już system plików, `mkfs.xfs` odmówi; dodaj `-f`, gdy na pewno chcesz go nadpisać.

```bash
# montujemy i sprawdzamy parametry (xfs_info działa na zamontowanym systemie plików)
sudo mkdir -p /mnt/dane
sudo mount /dev/sdb1 /mnt/dane
xfs_info /mnt/dane
```

Wyjście `xfs_info` wygląda identycznie jak wyjście `mkfs.xfs` – to ten sam opis struktury.

```bash
# etykieta: odczyt działa zawsze, zmiana tylko na ODMONTOWANYM systemie plików
sudo xfs_admin -l /dev/sdb1
sudo umount /mnt/dane
sudo xfs_admin -L archiwum /dev/sdb1
```

```text
label = "dane"
writing all SBs
new label = "archiwum"
```

`xfs_admin -U generate` nadaje nowy UUID – przydaje się po sklonowaniu dysku, gdy dwie partycje mają ten sam identyfikator.

```bash
# powiększenie: najpierw partycja lub wolumin LVM, potem system plików – NA ZAMONTOWANYM
sudo xfs_growfs /mnt/dane
```

```text
data blocks changed from 1310720 to 2621440
```

Bez argumentu `-D` XFS rośnie do końca dostępnego miejsca. Podajesz **punkt montowania**, nie urządzenie – to częsta pomyłka.

```bash
# sprawdzenie i naprawa: TYLKO na odmontowanym systemie plików
sudo umount /mnt/dane
sudo xfs_repair /dev/sdb1
```

```text
Phase 1 - find and verify superblock...
Phase 2 - using internal log
        - zero log...
        - scan filesystem freespace and inode maps...
Phase 3 - for each AG...
…
Phase 7 - verify and correct link counts...
done
```

Jeśli `xfs_repair` zgłosi, że dziennik zawiera niezatwierdzone zmiany, najpierw **zamontuj i odmontuj** partycję – to odtworzy dziennik. Opcję `-L` (wyzerowanie dziennika) stosuj dopiero, gdy montowanie się nie udaje; traci ostatnie zapisy. `xfs_repair -n` tylko sprawdza, nic nie zmienia – bezpieczny pierwszy krok.

Uwaga: polecenie `fsck.xfs` istnieje, ale nic nie robi (kończy się sukcesem). Dlatego w `/etc/fstab` dla XFS ostatnie pole ma wartość `0`.

## Najczęstsze błędy i pułapki

- **„Zmniejszę partycję, żeby zrobić miejsce na Windows/drugi wolumin”.** Na XFS się nie da. Kopia, `mkfs`, przywrócenie.
- **`xfs_growfs /dev/sdb1`** zamiast punktu montowania – błąd „not a mounted XFS filesystem”. Podaj katalog.
- **`xfs_repair` na zamontowanym systemie plików** – program odmówi. Na `/` użyj nośnika ratunkowego lub trybu ratunkowego z nośnika instalacyjnego.
- **`xfs_repair -L` jako pierwszy odruch.** Zeruje dziennik i traci ostatnie zapisy. Najpierw spróbuj zamontować.
- **Oczekiwanie `lost+found`.** XFS nie tworzy go przy `mkfs`; `xfs_repair` założy go dopiero, gdy znajdzie osierocone pliki.

## Podsumowanie

- XFS to domyślny system plików RHEL od wersji 7: skalowalny, równoległy, z dynamicznymi i-węzłami i dziennikiem metadanych.
- Jedno twarde ograniczenie: **nie da się go zmniejszyć**. Planuj rozmiary z LVM.
- Narzędzia mają przedrostek `xfs_`; `fsck` dla XFS nie istnieje – jest `xfs_repair`.
- Powiększanie na zamontowanym, naprawa i zmiana etykiety na odmontowanym.

| Polecenie | Co robi | Zamontowany? |
|---|---|---|
| `mkfs.xfs -L etykieta /dev/sdb1` | tworzy XFS (kasuje dane) | nie |
| `xfs_info /mnt/dane` | wypisuje strukturę systemu plików | tak |
| `xfs_admin -l` / `-L nowa /dev/sdb1` | odczyt / zmiana etykiety | odczyt tak, zmiana nie |
| `xfs_admin -U generate /dev/sdb1` | nowy UUID | nie |
| `xfs_growfs /mnt/dane` | powiększa do rozmiaru partycji | tak |
| `xfs_repair -n /dev/sdb1` | tylko sprawdza | nie |
| `xfs_repair /dev/sdb1` | naprawia | nie |
