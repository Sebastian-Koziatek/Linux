# Testowanie i diagnostyka sieci

> **W tej lekcji:** nauczysz się diagnozować „nie działa internet” metodą od dołu do góry oraz poznasz narzędzia: `ping`, `tracepath`, `dig`/`nslookup`/`host`, `ss`, `nc`, `mtr` i podstawy `nmap`.

„Nie działa sieć” to najczęstsze zgłoszenie, jakie dostaje administrator – i najmniej precyzyjne.
Przyczyną może być wyjęty kabel, literówka w masce, padnięty router, zepsuty DNS albo wyłączona
usługa na serwerze. Zamiast zgadywać, idziesz **od dołu do góry**: od własnej karty sieciowej,
przez bramę, internet i DNS, aż do konkretnej usługi. Pierwszy krok, który zawiedzie, wskazuje
warstwę z usterką.

## Jak to działa

![Pięć kroków diagnostyki: ip -br a (czy mam adres), ping do bramy, ping 8.8.8.8, ping onet.pl (DNS), curl -I (usługa); zatrzymaj się na pierwszym, który zawiedzie](../../grafiki/3-04-diagnostyka-krok-po-kroku.png)

| Krok | Pytanie | Polecenie | Jeśli zawiedzie, winna jest… |
|---|---|---|---|
| 1 | Czy mam adres i interfejs UP? | `ip -br a` | maszyna: kabel, interfejs, DHCP |
| 2 | Czy widzę bramę? | `ping -c 3 192.168.10.1` | sieć lokalna: switch, maska, adres bramy |
| 3 | Czy wychodzę w świat? | `ping -c 3 8.8.8.8` | trasa domyślna albo łącze dostawcy |
| 4 | Czy działa DNS? | `ping -c 3 onet.pl` | serwery DNS / `resolv.conf` |
| 5 | Czy działa usługa? | `curl -I https://onet.pl` | konkretna usługa lub port, nie Twoja sieć |

## W praktyce

### ping – puls sieci

```bash
# trzy pakiety do bramy; -c ogranicza liczbę (bez niej ping działa do Ctrl+C)
ping -c 3 192.168.10.1
```

```text
PING 192.168.10.1 (192.168.10.1) 56(84) bytes of data.
64 bytes from 192.168.10.1: icmp_seq=1 ttl=64 time=0.412 ms
64 bytes from 192.168.10.1: icmp_seq=2 ttl=64 time=0.388 ms
64 bytes from 192.168.10.1: icmp_seq=3 ttl=64 time=0.401 ms

--- 192.168.10.1 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2042ms
```

Liczy się podsumowanie: `0% packet loss` – łączność jest; `100% packet loss` – brak odpowiedzi.
`time=0.4 ms` to opóźnienie – w sieci lokalnej ułamki milisekund, przez internet kilkanaście–
kilkadziesiąt. Uwaga: niektóre maszyny celowo nie odpowiadają na ping (zapora) – brak odpowiedzi
nie zawsze oznacza „wyłączona”.

### tracepath / traceroute – którędy idzie pakiet

```bash
# pokazuje kolejne routery ("skoki") na drodze do celu
tracepath onet.pl
```

```text
 1?: [LOCALHOST]                       pmtu 1500
 1:  _gateway (192.168.10.1)           0.504ms
 2:  10.0.0.1                          1.312ms
 3:  ...
```

Gdy ping do internetu nie działa, `tracepath` pokaże, **gdzie** droga się urywa: na bramie, u
dostawcy, dalej. `traceroute` robi to samo (pakiet `traceroute`); `mtr` (pakiet `mtr`) łączy
traceroute z pingiem i odświeża wyniki na żywo – idealny na „sieć co chwilę przycina”.

### DNS: dig, nslookup, host

```bash
# pełna odpowiedź DNS (dig jest w pakiecie bind-utils)
dig onet.pl
```

```text
;; ANSWER SECTION:
onet.pl.        300  IN  A  75.2.104.207

;; SERVER: 192.168.10.1#53(192.168.10.1) (UDP)
```

Sekcja ANSWER to odpowiedź (rekord `A` = adres IPv4), a linia `SERVER` mówi, **który** serwer
DNS odpowiedział – bezcenne przy diagnozie. Pytanie u konkretnego serwera: `dig @8.8.8.8 onet.pl`
– jeśli to działa, a zwykłe `dig` nie, winny jest Twój serwer DNS, nie sieć.

```bash
# prostsze narzędzia z tego samego pakietu
nslookup onet.pl      # klasyk znany też z Windows
host onet.pl          # najkrótsza odpowiedź
```

### ss – kto nasłuchuje na portach

`ss` (*socket statistics*) zastąpił stare `netstat`:

```bash
# porty nasłuchujące: -t TCP, -u UDP, -l nasłuchujące, -p proces, -n numery bez tłumaczenia nazw
sudo ss -tulpn
```

```text
Netid State  Local Address:Port  Process
tcp   LISTEN       0.0.0.0:22    users:(("sshd",pid=1012,fd=3))
tcp   LISTEN     127.0.0.1:631   users:(("cupsd",pid=980,fd=7))
```

Czytanie: `sshd` nasłuchuje na porcie 22 na wszystkich adresach (`0.0.0.0`), a `cupsd` tylko
lokalnie (`127.0.0.1` – z sieci niedostępny). Gdy „usługa nie odpowiada”, najpierw sprawdź, czy
w ogóle nasłuchuje i na jakim adresie.

### nc – ręczny test portu

```bash
# czy port 22 na serwerze jest otwarty? (-z tylko test, -v gadatliwie)
nc -zv 192.168.10.20 22
```

```text
Ncat: Connected to 192.168.10.20:22.
```

`Connected` = port otwarty; `Connection refused` = maszyna żyje, ale nic tam nie nasłuchuje;
długie oczekiwanie i `timed out` = pakiety giną (zapora, zła trasa).

### nmap – skan własnej maszyny

`nmap` skanuje wiele portów naraz (pakiet `nmap`):

```bash
# jakie porty mam otwarte? skanujemy samych siebie
nmap localhost
```

```text
PORT    STATE SERVICE
22/tcp  open  ssh
631/tcp open  ipp
```

> **Ważna zasada:** skanuj **wyłącznie własne systemy** albo te, na których skan masz wyraźnie
> uzgodniony. Skanowanie cudzych maszyn jest traktowane jak przygotowanie do ataku – w wielu
> firmach i sieciach to incydent bezpieczeństwa.

Więcej o nmap – w [module 21](../../Dzia%C5%82%204%20-%20Tematy%20dodatkowe/07.%20nmap/1.%20nmap%20%E2%80%93%20wprowadzenie%20i%20etyka.md).

### curl – test z poziomu aplikacji

```bash
# -I pobiera same nagłówki odpowiedzi HTTP
curl -I https://onet.pl
```

```text
HTTP/2 200
content-type: text/html
```

`HTTP/2 200` oznacza: sieć, DNS i usługa WWW działają. Jeżeli wszystkie wcześniejsze kroki
przeszły, a `curl` zawodzi tylko dla jednej strony – problem leży po stronie tej usługi.

## Najczęstsze błędy i pułapki

- **Zaczynanie od środka.** „DNS nie działa!” – a tak naprawdę kabel wypadł. Zawsze od kroku 1.
- **`ping` bez `-c` w skrypcie.** Działa w nieskończoność; w skryptach zawsze `-c`.
- **Wniosek „host nie żyje” z samego pinga.** Zapora może wycinać ICMP – potwierdź drugim
  narzędziem (`nc -zv host 22`).
- **`ss -tulpn` bez `sudo`.** Zadziała, ale kolumna procesów będzie pusta – nazwy procesów
  widzi tylko root.
- **Skanowanie cudzych adresów nmapem** – patrz zasada wyżej.

## Podsumowanie

- Diagnozuj od dołu do góry: adres → brama → internet → DNS → usługa; zatrzymaj się na
  pierwszym kroku, który zawiedzie.
- `ping -c` sprawdza łączność, `tracepath`/`mtr` – drogę, `dig` – DNS, `ss -tulpn` – porty
  lokalne, `nc -zv` – port zdalny, `nmap` – wiele portów (tylko własne systemy!), `curl -I` –
  usługę WWW.

| Polecenie | Co sprawdza |
|---|---|
| `ip -br a` | adres i stan interfejsu |
| `ping -c 3 adres` | łączność do maszyny |
| `tracepath host` / `mtr host` | droga pakietów i miejsce awarii |
| `dig nazwa` / `dig @8.8.8.8 nazwa` | odpowiedź DNS (i konkretnego serwera) |
| `nslookup nazwa`, `host nazwa` | szybkie pytanie o nazwę |
| `sudo ss -tulpn` | porty nasłuchujące i procesy |
| `nc -zv host port` | czy pojedynczy zdalny port jest otwarty |
| `nmap localhost` | otwarte porty maszyny (tylko własnej) |
| `curl -I https://adres` | odpowiedź usługi WWW |
