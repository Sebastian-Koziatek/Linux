# Operacje na plikach i katalogach

> **W tej lekcji:** nauczysz się tworzyć, kopiować, przenosić i usuwać pliki oraz katalogi,
> wyświetlać zawartość plików, zapisywać wynik polecenia do pliku (`>` i `>>`) i wskazywać wiele
> plików naraz za pomocą symboli wieloznacznych `*`, `?`, `[]`.

Tworzenie, kopiowanie, przenoszenie, zmiana nazwy i usuwanie plików to w terminalu pojedyncze,
krótkie polecenia – odpowiednik tego, co w Eksploratorze robisz prawym przyciskiem myszy. W
odróżnieniu od Eksploratora możesz je wykonać na stu plikach naraz, na zdalnym serwerze, albo
zapisać w skrypcie, który uruchomi się sam o trzeciej w nocy.

Jest jedna ważna różnica, o której musisz pamiętać od pierwszej minuty: **w terminalu nie ma
Kosza**. Usunięty plik znika od razu i na dobre.

## Jak to działa

Każde polecenie z tej lekcji ma ten sam schemat: `polecenie [opcje] źródło cel`. Źródłem i celem
są ścieżki – bezwzględne lub względne, dokładnie tak, jak w poprzedniej lekcji. Jeśli celem jest
istniejący katalog, plik ląduje **w nim**; jeśli celem jest nowa nazwa, plik dostaje **tę nazwę**.

Jeszcze jedna zasada: polecenia uniksowe **milczą, gdy się udało**. Brak komunikatu po `cp` czy
`rm` oznacza sukces. Komunikat pojawia się tylko przy błędzie. Jeśli chcesz widzieć, co się dzieje,
dodaj opcję `-v` (ang. *verbose* – gadatliwy).

## W praktyce

Pracuj w katalogu domowym – tam możesz wszystko tworzyć i kasować bez ryzyka.

### Tworzenie: `mkdir`, `touch`

```bash
# nowy katalog
mkdir projekt
```

```bash
# cała ścieżka naraz – -p tworzy brakujące katalogi po drodze i nie narzeka, gdy już istnieją
mkdir -p projekt/dane/2026
```

```bash
# kilka katalogów jednym poleceniem
mkdir projekt/kopie projekt/raporty
```

```bash
# pusty plik (albo odświeżenie daty istniejącego)
touch projekt/notatki.txt
```

```bash
# kilka plików naraz
touch projekt/a.txt projekt/b.txt projekt/c.txt
```

### Oglądanie: `cat`, `echo`

```bash
# wpisz tekst na ekran
echo "Witaj w Linuksie"
```

```text
Witaj w Linuksie
```

```bash
# wyświetl całą zawartość pliku
cat /etc/hostname
```

```text
serwer
```

`cat` wypisuje cały plik naraz – dla długich plików lepszy jest `less plik` (przewijasz
strzałkami, wychodzisz klawiszem `q`), `head plik` (pierwsze 10 wierszy) albo `tail plik`
(ostatnie 10). Te narzędzia szerzej omawia moduł
[Zarządzanie plikami i katalogami](../2.%20Zarz%C4%85dzanie%20plikami%20i%20katalogami/1.%20Uprawnienia%20do%20plik%C3%B3w%20i%20katalog%C3%B3w.md).

### Przekierowania: `>` i `>>`

Normalnie wynik polecenia trafia na ekran. Znak `>` kieruje go do pliku **zamiast** na ekran.

![Wynik na ekran, > nadpisuje plik, >> dopisuje do pliku](../../grafiki/2-1-przekierowania.png)

```bash
# utwórz plik z jednym wierszem tekstu (jeśli plik istniał – jego treść ZNIKA)
echo "pierwszy wiersz" > projekt/lista.txt
```

```bash
# dopisz kolejny wiersz na końcu (treść zostaje)
echo "drugi wiersz" >> projekt/lista.txt
cat projekt/lista.txt
```

```text
pierwszy wiersz
drugi wiersz
```

```bash
# zapisz do pliku wynik dowolnego polecenia, np. listę plików z /etc
ls -l /etc > projekt/spis-etc.txt
```

Zapamiętaj: **jeden znak nadpisuje, dwa dopisują**. Pomyłka `>` zamiast `>>` kasuje zawartość
pliku bez pytania.

### Kopiowanie: `cp`

```bash
# kopia pliku pod nową nazwą
cp projekt/lista.txt projekt/lista-kopia.txt
```

```bash
# kopia do istniejącego katalogu – nazwa zostaje ta sama
cp projekt/lista.txt projekt/kopie/
```

```bash
# katalog kopiujesz z -r (rekurencyjnie – razem z zawartością); bez -r cp odmówi
cp -r projekt projekt-kopia
```

```bash
# -i pyta przed nadpisaniem istniejącego pliku, -v pokazuje, co kopiuje
cp -iv projekt/lista.txt projekt/kopie/
```

```text
cp: zastąpić 'projekt/kopie/lista.txt'? n
```

### Przenoszenie i zmiana nazwy: `mv`

W Linuksie to **jedno polecenie**: przenieść plik do innej nazwy w tym samym katalogu to po prostu
zmiana nazwy.

```bash
# zmiana nazwy
mv projekt/notatki.txt projekt/notatki-stare.txt
```

```bash
# przeniesienie do innego katalogu (nazwa bez zmian)
mv projekt/notatki-stare.txt projekt/kopie/
```

```bash
# przeniesienie i zmiana nazwy naraz
mv projekt/a.txt projekt/raporty/styczen.txt
```

```bash
# zmiana nazwy katalogu – też mv, bez żadnego -r
mv projekt-kopia projekt-archiwum
```

`mv` nadpisuje istniejący plik docelowy bez pytania – `mv -i` zapyta.

### Usuwanie: `rm`, `rmdir`

```bash
# usuń plik
rm projekt/b.txt
```

```bash
# usuń kilka plików, pytając o każdy
rm -i projekt/c.txt projekt/lista-kopia.txt
```

```text
rm: usunąć zwykły pusty plik 'projekt/c.txt'? t
rm: usunąć zwykły plik 'projekt/lista-kopia.txt'? t
```

```bash
# usuń PUSTY katalog – rmdir odmówi, jeśli coś w nim jest (to zabezpieczenie)
rmdir projekt/dane/2026
```

```bash
# usuń katalog razem z całą zawartością
rm -r projekt-archiwum
```

> **UWAGA – `rm -rf` i brak Kosza**
>
> `rm` nie przenosi niczego do Kosza. Usunięty plik znika natychmiast, a odzyskanie go
> jest trudne lub niemożliwe. Opcja `-r` usuwa katalog ze wszystkim, co w nim jest; opcja `-f`
> (ang. *force*) wyłącza pytania i komunikaty o błędach. Razem – `rm -rf` – kasują wszystko,
> co wskażesz, bez jednego pytania.
>
> Klasyczne katastrofy:
> - `rm -rf /` lub `rm -rf /*` – kasuje cały system (nowoczesny `rm` odmawia dla samego `/`,
>   ale nie dla `/*`).
> - `rm -rf ~` – kasuje cały katalog domowy.
> - `rm -rf $KATALOG/` gdy zmienna `KATALOG` jest pusta – staje się `rm -rf /`.
> - `rm -rf * .bak` (spacja przed kropką) – kasuje wszystko w bieżącym katalogu, a potem narzeka,
>   że `.bak` nie istnieje.
>
> Nawyki, które chronią: przed `rm -r` zrób `ls` tej samej ścieżki i zobacz, co zniknie;
> używaj `rm -i` lub aliasu `rm='rm -i'` (lekcja [Zmienne i aliasy](9.%20Zmienne%20i%20aliasy.md));
> jako `root` myśl dwa razy dłużej; nigdy nie wklejaj z internetu polecenia z `rm -rf`,
> którego nie rozumiesz.

### Symbole wieloznaczne: `*`, `?`, `[]`

Zamiast wymieniać pliki po kolei, opisz je wzorcem. Wzorzec rozwija **powłoka**, zanim uruchomi
polecenie – dlatego działa z każdym poleceniem: `ls`, `cp`, `mv`, `rm`.

| Symbol | Znaczenie | Przykład |
|---|---|---|
| `*` | dowolny ciąg znaków (także pusty) | `*.txt` – wszystkie pliki z końcówką `.txt`; `raport*` – zaczynające się od „raport” |
| `?` | dokładnie jeden dowolny znak | `plik?.txt` – `plik1.txt`, `plikA.txt`, ale nie `plik10.txt` |
| `[abc]` | jeden znak z listy | `raport[123].txt` – `raport1.txt`, `raport2.txt`, `raport3.txt` |
| `[a-z]`, `[0-9]` | jeden znak z zakresu | `log[0-9].txt` |
| `{a,b}` | każda z wymienionych wartości (to nie wzorzec, tylko „rozwinięcie”) | `touch plik{1..5}.txt` tworzy pięć plików |

```bash
# przygotuj pliki do ćwiczeń
cd projekt
touch raport1.txt raport2.txt raport10.txt notatka.md zdjecie.jpg
```

```bash
# wszystkie pliki .txt
ls *.txt
```

```text
lista.txt  raport1.txt  raport10.txt  raport2.txt  spis-etc.txt
```

```bash
# raport + dokładnie jeden znak + .txt
ls raport?.txt
```

```text
raport1.txt  raport2.txt
```

```bash
# skopiuj wszystkie raporty do katalogu raporty
cp raport*.txt raporty/
```

```bash
# usuń wszystkie pliki .jpg – najpierw sprawdź tym samym wzorcem, co zniknie
ls *.jpg
rm *.jpg
```

Ten ostatni nawyk – **najpierw `ls wzorzec`, potem `rm wzorzec`** – oszczędził już wiele danych.

## Najczęstsze błędy i pułapki

1. **`cp katalog cel` bez `-r`.** Zobaczysz *-r nie podano; pominięto katalog*. Katalogi kopiuje
   się zawsze z `-r`.
2. **`>` zamiast `>>`.** Jeden znak więcej, cała różnica: zawartość pliku bezpowrotnie nadpisana.
3. **`rm *` w złym katalogu.** Przed każdym `rm` ze wzorcem – `pwd` i `ls` z tym samym wzorcem.
4. **`mv` nadpisuje bez ostrzeżenia.** Jeśli w katalogu docelowym jest plik o tej samej nazwie,
   znika. `mv -i` pyta.
5. **Spacje i gwiazdka.** `rm * .txt` to dwa argumenty: `*` (wszystko) i `.txt`. Miało być `*.txt`.
6. **Polecenie „nic nie powiedziało”.** To znaczy, że się udało. Sprawdź `ls`, jeśli nie wierzysz.

## Podsumowanie

- Cel będący katalogiem = plik ląduje w środku; cel będący nową nazwą = plik zmienia nazwę.
- `mv` to zarówno przenoszenie, jak i zmiana nazwy. Katalogi kopiujesz i usuwasz z `-r`.
- `>` nadpisuje, `>>` dopisuje. Oba tworzą plik, jeśli go nie było.
- `*` wiele znaków, `?` jeden znak, `[...]` jeden znak z listy – rozwija je powłoka.
- Nie ma Kosza. `rm -rf` wykonuje się bez pytań. Sprawdzaj `ls`, zanim skasujesz.

| Polecenie | Co robi |
|---|---|
| `mkdir -p a/b/c` | utwórz katalog (z całą ścieżką) |
| `touch plik` | utwórz pusty plik |
| `cat plik` | wyświetl zawartość |
| `echo "tekst" > plik` | zapisz tekst do pliku (nadpisz) |
| `echo "tekst" >> plik` | dopisz tekst na końcu pliku |
| `cp zrodlo cel` | kopiuj plik; `cp -r` – katalog |
| `mv zrodlo cel` | przenieś lub zmień nazwę |
| `rm plik` | usuń plik; `rm -i` – pytaj |
| `rm -r katalog` | usuń katalog z zawartością |
| `rmdir katalog` | usuń pusty katalog |
| `ls *.txt` | pliki pasujące do wzorca |
