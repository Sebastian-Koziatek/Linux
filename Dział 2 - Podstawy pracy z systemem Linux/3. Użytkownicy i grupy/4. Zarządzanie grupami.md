# Zarządzanie grupami

> **W tej lekcji:** nauczysz się tworzyć, zmieniać i usuwać grupy, zarządzać ich członkami poleceniem `gpasswd` oraz zbudujesz kompletny katalog współdzielony dla zespołu.

Wiesz już [po co są grupy](2.%20Po%20co%20są%20grupy.md). Teraz strona praktyczna: dział księgowości prosi o wspólny katalog na faktury. Założysz grupę, dodasz do niej ludzi i skonfigurujesz katalog tak, żeby wszystko, co w nim powstanie, od razu należało do zespołu. Ten scenariusz – grupa + katalog z SGID – powtarza się w pracy administratora nieustannie: projekty, działy, wspólne repozytoria plików.

## Jak to działa

Grupy mieszkają w pliku `/etc/group` (jeden wiersz = jedna grupa z listą członków) i mają swoje numery **GID** (ang. group ID). Zarządzają nimi cztery polecenia:

- `groupadd` / `groupmod` / `groupdel` – tworzenie, zmiana, usuwanie grupy,
- `gpasswd` – zarządzanie członkami (prostsze niż `usermod`, bo nie dotyka pozostałych grup użytkownika).

Członkostwo można też nadawać przez `usermod -aG grupa user` – efekt jest ten sam; `gpasswd` bywa wygodniejszy, bo myśli „od strony grupy”.

## W praktyce

### Tworzenie, zmiana i usuwanie grupy

```bash
# nowa grupa dla działu
sudo groupadd ksiegowosc

# sprawdzenie wpisu (getent pyta system o konto/grupę niezależnie od źródła)
getent group ksiegowosc
```

```text
ksiegowosc:x:1005:
```

```bash
# zmiana nazwy grupy (-n) – GID i dostęp do plików zostają
sudo groupmod -n finanse ksiegowosc

# zmiana numeru GID (-g); pliki ze starym GID trzeba potem przestawić ręcznie
sudo groupmod -g 2000 finanse

# usunięcie grupy (nie może być niczyją grupą główną)
sudo groupdel finanse
```

Po `groupdel` pliki, które należały do grupy, pokazują w `ls -l` sam numer GID. Znajdziesz je poleceniem `sudo find / -nogroup 2>/dev/null`.

### Członkowie grupy: gpasswd

```bash
# dodanie i usunięcie pojedynczej osoby
sudo gpasswd -a anna ksiegowosc
sudo gpasswd -d anna ksiegowosc

# ustawienie całej listy członków za jednym razem (M = members)
sudo gpasswd -M anna,jan,ewa ksiegowosc

# kto należy do grupy
getent group ksiegowosc
```

```text
ksiegowosc:x:1005:anna,jan,ewa
```

| Polecenie | Co robi |
|---|---|
| `gpasswd -a user grupa` | dodaje jednego użytkownika |
| `gpasswd -d user grupa` | usuwa jednego użytkownika |
| `gpasswd -M lista grupa` | **zastępuje** całą listę członków |
| `gpasswd -A user grupa` | wyznacza administratora grupy (może sam dodawać członków) |

Jak zawsze: świeżo dodany członek widzi grupę dopiero po ponownym zalogowaniu.

### newgrp – grupa „na już”

Jeśli nie możesz się przelogować, `newgrp` otwiera nową powłokę, w której podana grupa staje się Twoją grupą główną:

```bash
# doraźnie pracuj jako członek ksiegowosc (wyjście: exit)
newgrp ksiegowosc
id
```

W tej powłoce nowe pliki będą należeć do `ksiegowosc`. To obejście na jedną sesję – docelowo po prostu przeloguj się.

### Scenariusz: katalog współdzielony działu

Cel: `/srv/ksiegowosc`, w którym anna, jan i ewa swobodnie pracują nad wspólnymi plikami, a nikt spoza działu nie ma wstępu.

```bash
# 1. Grupa i członkowie
sudo groupadd ksiegowosc
sudo gpasswd -M anna,jan,ewa ksiegowosc

# 2. Katalog: właściciel root, grupa działu
sudo mkdir -p /srv/ksiegowosc
sudo chown root:ksiegowosc /srv/ksiegowosc

# 3. Uprawnienia 2770: grupa ma pełne prawa, inni nic,
#    a dwójka z przodu (SGID) sprawia, że nowe pliki dziedziczą grupę katalogu
sudo chmod 2770 /srv/ksiegowosc
ls -ld /srv/ksiegowosc
```

```text
drwxrws---. 2 root ksiegowosc 4096 Oct 18 11:00 /srv/ksiegowosc
```

```bash
# 4. Test jako anna (po jej ponownym zalogowaniu)
sudo -u anna touch /srv/ksiegowosc/faktura-001.txt
ls -l /srv/ksiegowosc
```

```text
-rw-rw-r--. 1 anna ksiegowosc 0 Oct 18 11:02 faktura-001.txt
```

Plik anny należy do grupy `ksiegowosc` (dzięki SGID), a jej domyślna maska `0002` daje grupie prawo zapisu – jan i ewa mogą plik edytować. Bez SGID plik należałby do prywatnej grupy `anna` i reszta zespołu mogłaby go najwyżej czytać.

> **Chcesz, żeby usuwać pliki mógł tylko ich autor?** Dodaj bit sticky, jak w `/tmp`: `sudo chmod 3770 /srv/ksiegowosc` (3 = SGID 2 + sticky 1).

## Najczęstsze błędy i pułapki

- **`gpasswd -M` zastępuje listę** – jeśli chcesz tylko dodać osobę, użyj `-a`, inaczej wyrzucisz pozostałych.
- **`groupdel` odmawia** (`cannot remove the primary group`) – grupa jest czyjąś grupą główną. Najpierw zmień użytkownikowi grupę główną (`usermod -g`) albo usuń konto.
- **Pliki w katalogu zespołu należą do prywatnych grup autorów** – zapomniany SGID. Napraw: `sudo chmod g+s katalog` i wyrównaj istniejące pliki `sudo chgrp -R ksiegowosc katalog`.
- **Członek grupy nie może edytować cudzych plików** – autor ma maskę `077`/`022`; pliki powstają bez `w` dla grupy. Rozwiązanie: `umask 002` dla członków zespołu albo świadome `chmod g+w`.
- **Zmiany „nie działają”** – jak zwykle: ponowne logowanie.

## Podsumowanie

- `groupadd`, `groupmod`, `groupdel` zarządzają samą grupą; `gpasswd -a/-d/-M` – jej członkami.
- `getent group nazwa` pokazuje skład grupy.
- Katalog zespołu = `chown root:grupa` + `chmod 2770`; SGID daje dziedziczenie grupy przez nowe pliki.
- `newgrp` zmienia grupę główną na czas jednej sesji.

| Polecenie | Co robi |
|---|---|
| `sudo groupadd ksiegowosc` | utwórz grupę |
| `sudo groupmod -n nowa stara` | zmień nazwę grupy |
| `sudo groupdel ksiegowosc` | usuń grupę |
| `sudo gpasswd -a anna ksiegowosc` | dodaj członka |
| `sudo gpasswd -d anna ksiegowosc` | usuń członka |
| `sudo gpasswd -M anna,jan ksiegowosc` | ustaw pełną listę członków |
| `getent group ksiegowosc` | pokaż grupę i członków |
| `newgrp ksiegowosc` | sesja z inną grupą główną |
| `sudo chmod 2770 katalog` | katalog zespołowy z SGID |
