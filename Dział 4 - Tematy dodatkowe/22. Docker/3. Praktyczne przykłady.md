# Praktyczne przykłady

> **W tej lekcji:** uruchomisz serwer WWW z własną stroną, bazę PostgreSQL z trwałymi danymi,
> zbudujesz własny obraz z pliku Containerfile i nauczysz się sprzątać po kontenerach.

## Po co mi to?

Polecenia z poprzedniej lekcji nabierają sensu dopiero złożone w całość. Trzy scenariusze poniżej
to miniatury prawdziwych zadań administratora: wystawić stronę, postawić bazę tak, by dane przeżyły
wymianę kontenera, i zapakować własną aplikację w obraz.

## Jak to działa

Wszystkie przykłady działają na Podmanie bez roota. Obrazy pobieramy z pełnych adresów
(`docker.io/library/…`), porty mapujemy powyżej 1024, a na woluminach pamiętamy o `:Z` (SELinux).

## W praktyce

### Przykład 1: nginx z własną stroną

```bash
# katalog ze stroną po stronie gospodarza
mkdir -p ~/strona
cat > ~/strona/index.html <<'EOF'
<h1>Serwer szkoleniowy</h1>
<p>Ta strona jest serwowana z kontenera.</p>
EOF
```

```bash
# nginx w tle, strona z wolumenu, port 8080
podman run -d --name www -p 8080:80 -v ~/strona:/usr/share/nginx/html:Z docker.io/library/nginx
```

```bash
# test
curl http://localhost:8080
```

```text
<h1>Serwer szkoleniowy</h1>
<p>Ta strona jest serwowana z kontenera.</p>
```

Edytujesz `~/strona/index.html` – zmiana jest widoczna od razu, bez restartu kontenera.
Żeby strona była widoczna z innych maszyn, otwórz jeszcze port na firewallu
(`sudo firewall-cmd --add-port=8080/tcp`).

### Przykład 2: PostgreSQL z trwałymi danymi

Baza danych to klasyczny przypadek na wolumen – dane muszą przetrwać wymianę kontenera:

```bash
# katalog na dane i kontener bazy; zmienna -e ustawia hasło administratora
mkdir -p ~/pgdata
podman run -d --name baza \
  -e POSTGRES_PASSWORD=tajnehaslo \
  -v ~/pgdata:/var/lib/postgresql/data:Z \
  -p 5432:5432 \
  docker.io/library/postgres:16
```

```bash
# klient psql jest w samym kontenerze – tworzymy tabelę i wpis
podman exec -it baza psql -U postgres -c "CREATE TABLE goscie(imie text); INSERT INTO goscie VALUES ('anna');"
```

Teraz dowód, że dane żyją poza kontenerem:

```bash
# kasujemy kontener... i stawiamy nowy na tym samym wolumenie
podman rm -f baza
podman run -d --name baza2 -e POSTGRES_PASSWORD=tajnehaslo \
  -v ~/pgdata:/var/lib/postgresql/data:Z docker.io/library/postgres:16
podman exec -it baza2 psql -U postgres -c "SELECT * FROM goscie;"
```

```text
 imie
------
 anna
(1 row)
```

### Przykład 3: własny obraz z Containerfile

Własny obraz opisuje się w pliku `Containerfile` (nazwa dockerowa `Dockerfile` też działa).
Zbudujemy obraz z narzędziami diagnostycznymi i skryptem powitalnym:

```bash
mkdir -p ~/moj-obraz && cd ~/moj-obraz
cat > Containerfile <<'EOF'
# obraz bazowy – minimalny wariant systemu zgodnego z RHEL 9
FROM quay.io/rockylinux/rockylinux:9-minimal

# metadane i instalacja pakietów (jedna warstwa = jedno RUN)
LABEL opis="Obraz diagnostyczny ze szkolenia"
RUN microdnf install -y iputils bind-utils && microdnf clean all

# skrypt startowy
RUN echo 'echo "Diagnostyka: $(date)"; ping -c 2 $CEL' > /start.sh && chmod +x /start.sh

# domyślna zmienna i polecenie uruchamiane przy starcie kontenera
ENV CEL=localhost
CMD ["/bin/bash", "/start.sh"]
EOF
```

```bash
# budowa obrazu o nazwie diagnostyka i uruchomienie
podman build -t diagnostyka .
podman run --rm -e CEL=localhost diagnostyka
```

```text
Diagnostyka: Sat Oct 18 12:30:11 UTC 2026
PING localhost (127.0.0.1) 56(84) bytes of data.
64 bytes from localhost (127.0.0.1): icmp_seq=1 ttl=64 time=0.041 ms
...
```

Dziesięć linii pliku – i masz powtarzalny, przenośny obraz. Tak samo pakuje się własne aplikacje:
`FROM` baza, `RUN` instalacje, `COPY` pliki aplikacji, `CMD` uruchomienie.

> **Wzmianka o compose:** gdy usług jest kilka (aplikacja + baza + cache), ich wspólny opis trzyma
> się w jednym pliku YAML i uruchamia narzędziem `podman-compose` (odpowiednik `docker compose`).
> Na szkoleniu zostajemy przy pojedynczych kontenerach.

### Sprzątanie

Kontenery i obrazy potrafią zjeść zaskakująco dużo dysku:

```bash
podman system df          # ile miejsca zajmują obrazy, kontenery i woluminy
```

```bash
# usuń zatrzymane kontenery i nieużywane obrazy (zapyta o potwierdzenie)
podman container prune
podman image prune
```

```bash
# wielkie sprzątanie: wszystko, co nieużywane, łącznie z obrazami bez kontenerów
podman system prune -a
```

`prune` nie tyka działających kontenerów ani ich obrazów, ale usuwa wszystko „luzem” –
upewnij się najpierw, że żaden zatrzymany kontener nie będzie Ci jeszcze potrzebny.

## Najczęstsze błędy i pułapki

- **Hasło bazy w historii powłoki.** `-e POSTGRES_PASSWORD=…` zostaje w `history`. W prawdziwych
  wdrożeniach używa się plików z sekretami (`podman secret`); na szkoleniu wystarczy świadomość.
- **Wolumen bazy bez `:Z`** – PostgreSQL nie wystartuje z powodu SELinuksa; `podman logs baza`
  pokaże błąd uprawnień.
- **`podman build` w katalogu domowym pełnym plików.** Budowa wysyła cały katalog jako kontekst –
  twórz obrazy w osobnym, małym katalogu.
- **Wersja `latest`.** `postgres:16` jest przewidywalny; `postgres:latest` może po roku oznaczać
  zupełnie inną wersję. W obrazach bazowych zawsze podawaj wersję.
- **Sprzątanie `prune -a` na współdzielonej maszynie** – usuniesz obrazy, które ktoś pobrał
  do swojej pracy. Na wspólnych serwerach sprzątaj wybiórczo (`rm`/`rmi` po nazwie).

## Podsumowanie

- Strona WWW: nginx + wolumen z plikami + `-p 8080:80`; zmiany w plikach widać natychmiast.
- Baza: dane na wolumenie przeżywają usunięcie i wymianę kontenera – to wzorzec dla wszystkich
  usług z danymi.
- Własny obraz: `Containerfile` (`FROM`, `RUN`, `ENV`, `CMD`) + `podman build -t nazwa .`.
- Kilka usług naraz opisuje się w compose – do doczytania po szkoleniu.
- Dysk ratuje `podman system df` + `prune`.

| Zadanie | Polecenie |
|---|---|
| nginx z własną stroną | `podman run -d -p 8080:80 -v ~/strona:/usr/share/nginx/html:Z docker.io/library/nginx` |
| baza z trwałymi danymi | `podman run -d -e POSTGRES_PASSWORD=… -v ~/pgdata:/var/lib/postgresql/data:Z docker.io/library/postgres:16` |
| polecenie w kontenerze | `podman exec -it baza psql -U postgres` |
| budowa obrazu | `podman build -t nazwa .` |
| zużycie dysku | `podman system df` |
| sprzątanie | `podman system prune -a` |
