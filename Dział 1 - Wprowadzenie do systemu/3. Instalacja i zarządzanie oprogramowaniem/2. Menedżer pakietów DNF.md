# Menedżer pakietów DNF

> **W tej lekcji:** poznasz polecenie `dnf` – menedżer pakietów rodziny Red Hat – i jego podstawowe podpolecenia: wyszukiwanie, instalację, usuwanie, aktualizację i historię. Dowiesz się też, dlaczego w starszych instrukcjach w tym samym miejscu stoi `yum`.

`dnf` to narzędzie, którym na co dzień instalujesz i aktualizujesz oprogramowanie w RHEL, Rocky Linux, AlmaLinux, CentOS Stream i Fedorze. Pobiera pakiety z repozytoriów, sam dolicza zależności, pamięta, co i kiedy zrobił, i potrafi to cofnąć. To pierwsze polecenie, które wpisujesz na świeżo zainstalowanym serwerze – i jedno z tych, których będziesz używać codziennie.

## Jak to działa

### Skąd się wziął `dnf` i dlaczego wszędzie widać `yum`

**DNF** (*Dandified YUM*) zastąpił starszy **YUM** (*Yellowdog Updater, Modified*) i od **RHEL 8** jest domyślnym menedżerem pakietów. YUM był domyślny w RHEL 5, 6 i 7 oraz w klasycznym CentOS-ie – stąd jego nazwa w starszych poradnikach, na forach, w odziedziczonych skryptach i w dokumentacji producentów sprzętu.

Polecenie `yum` nadal działa, bo zostawiono je dla zgodności:

```bash
# dokąd prowadzi plik /usr/bin/yum?
ls -l /usr/bin/yum
```

```text
lrwxrwxrwx. 1 root root 5 ... /usr/bin/yum -> dnf-3
```

`/usr/bin/yum` jest **dowiązaniem symbolicznym** (skrótem) do programu `dnf`. Cokolwiek wpiszesz po `yum`, wykona `dnf`. Dlatego:

- oba polecenia mają te same podpolecenia i opcje,
- oba czytają tę samą konfigurację (`/etc/dnf/dnf.conf`, `/etc/yum.repos.d/`),
- mają wspólną historię transakcji.

Praktyczny wniosek: starą instrukcję z `yum install` czytasz tak, jakby było w niej `dnf install`, a **sam piszesz `dnf`** – w terminalu, w skryptach i w notatkach. Nazwa `yum` została też w nazwach plików i katalogów (`/etc/yum.repos.d/`) oraz pakietu narzędzi `yum-utils`; tego nie zmieniaj.

> **RHEL 10 i nowa Fedora:** działa tam **dnf5** – przepisana, szybsza wersja. Polecenia z tej lekcji są identyczne, różnice dotyczą wtyczek i pojedynczych opcji.

> **Na Ubuntu/Debianie:** odpowiednikiem jest `apt` (dawniej `apt-get`). Porównanie poleceń znajdziesz w lekcji [6. Menedżery pakietów innych dystrybucji](6.%20Menedżery%20pakietów%20innych%20dystrybucji.md).

## W praktyce

Wszystkie polecenia, które **zmieniają** system (instalacja, usuwanie, aktualizacja), wymagają `sudo`. Polecenia, które tylko **pytają** (search, info, list), działają bez niego.

### Wyszukiwanie

```bash
# szukamy pakietów, których nazwa lub opis zawiera słowo „htop”
dnf search htop
```

```text
=================== Nazwa dokładnie dopasowana: htop ===================
htop.x86_64 : Interactive process viewer
```

Jeśli szukanego programu nie ma, lista będzie pusta – wtedy warto sprawdzić, czy nie siedzi w dodatkowym repozytorium (np. EPEL, lekcja 3).

### Informacje o pakiecie

```bash
# opis, wersja, rozmiar, licencja – bez instalowania
dnf info htop
```

```text
Dostępne pakiety
Nazwa         : htop
Wersja        : 3.2.2
Wydanie       : 1.el9
Architektura  : x86_64
Rozmiar       : 196 k
Źródło        : htop-3.2.2-1.el9.src.rpm
Repozytorium  : epel
Podsumowanie  : Interactive process viewer
Adres URL     : http://hisham.hm/htop/
Licencja      : GPLv2+
Opis          : htop is an interactive text-mode process viewer ...
```

W wierszu „Repozytorium” widzisz, skąd pakiet pochodzi. Pakiety już zainstalowane pokażą się w sekcji „Zainstalowane pakiety”.

### Instalacja i usuwanie

```bash
# instalacja; -y odpowiada „tak” na pytanie o potwierdzenie
sudo dnf install -y htop

# usunięcie pakietu (pliki konfiguracyjne zmienione przez Ciebie zostają jako .rpmsave)
sudo dnf remove htop
```

Można podać kilka pakietów naraz: `sudo dnf install wget mc tree`.

### Aktualizacja

```bash
# co jest do zaktualizowania? (nic nie zmienia)
dnf check-update

# aktualizacja wszystkiego
sudo dnf upgrade

# aktualizacja jednego pakietu
sudo dnf upgrade openssl
```

`dnf check-update` kończy się kodem wyjścia 100, gdy są aktualizacje – to normalne, nie błąd. `dnf upgrade` i `dnf update` robią dokładnie to samo: `update` zostawiono jako alias ze starego YUM-a, gdzie te dwa polecenia różniły się obsługą pakietów przestarzałych.

### Co jest zainstalowane

```bash
# pełna lista zainstalowanych pakietów (długa – warto przefiltrować)
dnf list installed

# tylko pakiety z „ssh” w nazwie
dnf list installed | grep ssh
```

```text
libssh.x86_64                0.10.4-13.el9        @anaconda
openssh.x86_64               8.7p1-38.el9         @anaconda
openssh-clients.x86_64       8.7p1-38.el9         @anaconda
openssh-server.x86_64        8.7p1-38.el9         @anaconda
```

`@anaconda` oznacza: zainstalowane przez instalator systemu.

### Historia

Każda instalacja, usunięcie i aktualizacja to **transakcja** z numerem. Dzięki temu widzisz, co i kiedy się zmieniło, i możesz to cofnąć.

```bash
# lista transakcji, od najnowszej
dnf history
```

```text
ID     | Wiersz poleceń           | Data i czas      | Działania   | Zmien.
-------------------------------------------------------------------------
     5 | install -y htop          | 2026-10-18 10:12 | Install     |    1
     4 | remove nginx             | 2026-10-18 09:58 | Removed     |    4
     3 | install nginx            | 2026-10-18 09:40 | Install     |    4
```

```bash
# szczegóły jednej transakcji
dnf history info 3

# cofnięcie transakcji nr 5 (czyli usunięcie htop)
sudo dnf history undo 5
```

Więcej o historii i cofaniu w lekcji [5. DNF – możliwości zaawansowane](5.%20DNF%20–%20możliwości%20zaawansowane.md).

## Najczęstsze błędy i pułapki

- **„Nie znaleziono dopasowania dla argumentu”** – literówka w nazwie albo pakiet jest w repozytorium, którego nie masz włączonego. Najpierw `dnf search`, potem `dnf install`.
- **Przerwanie `dnf upgrade` w połowie** (zamknięcie terminala, utrata sieci). System może zostać z pakietami w pół drogi. Nie panikuj: uruchom `sudo dnf upgrade` ponownie – DNF dokończy transakcję. Długie aktualizacje lepiej uruchamiać w `tmux`/`screen` albo lokalnie na konsoli.
- **`dnf install plik.rpm` z katalogu bieżącego bez `./`** – `dnf` pomyśli, że to nazwa pakietu z repozytorium. Pisz `sudo dnf install ./plik.rpm`.
- **Automatyczne `-y` w skryptach bez zastanowienia.** `-y` potwierdza wszystko, także usunięcie 200 pakietów przy konflikcie zależności. W skryptach używaj go świadomie, a w terminalu czytaj podsumowanie.
- **Przepisywanie starych skryptów „jeden do jednego”.** Polecenia działają, ale skrypt z `yum` na nowym systemie myli czytelnika. Przy okazji zmiany zamień `yum` na `dnf` – efekt będzie identyczny.

## Podsumowanie

- `dnf` to menedżer pakietów RHEL 8/9/10 i pochodnych; `yum` to jego poprzednik, dziś zwykłe dowiązanie do `dnf`.
- Pytania (`search`, `info`, `list`) bez `sudo`; zmiany (`install`, `remove`, `upgrade`) z `sudo`.
- Każda zmiana to transakcja z numerem w `dnf history` – da się ją cofnąć.

| Polecenie | Co robi |
|---|---|
| `dnf search słowo` | szuka w nazwach i opisach pakietów |
| `dnf info pakiet` | opis, wersja, repozytorium |
| `sudo dnf install pakiet` | instaluje z zależnościami |
| `sudo dnf remove pakiet` | usuwa pakiet |
| `dnf check-update` | pokazuje dostępne aktualizacje |
| `sudo dnf upgrade` | aktualizuje wszystko (lub wskazany pakiet) |
| `dnf list installed` | lista zainstalowanych |
| `dnf history` | lista transakcji |
| `sudo dnf history undo N` | cofa transakcję nr N |
