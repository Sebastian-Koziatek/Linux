# Menedżer pakietów YUM

> **W tej lekcji:** poznasz polecenie `yum` – klasyczny menedżer pakietów rodziny Red Hat – i jego podstawowe podpolecenia: wyszukiwanie, instalację, usuwanie, aktualizację i historię. Dowiesz się też, dlaczego na RHEL 9/10 `yum` i `dnf` to w praktyce to samo.

`yum` to menedżer pakietów używany w RHEL 5, 6 i 7, którego nazwę do dziś spotkasz wszędzie: w starszych instrukcjach, na forach, w skryptach odziedziczonych po poprzednikach i w dokumentacji producentów sprzętu. Współcześnie zastąpił go `dnf`, ale polecenie `yum` nadal działa – i oba wymagają od administratora tej samej wiedzy.

## Jak to działa

### Trochę historii

**YUM** to skrót od *Yellowdog Updater, Modified*. Powstał na początku lat 2000 jako nakładka na `rpm`, która potrafiła pobierać pakiety z repozytoriów i rozwiązywać zależności. Przez lata był domyślnym menedżerem pakietów w RHEL 5, 6 i 7 oraz CentOS-ie.

Z czasem jego ograniczenia (wolne rozwiązywanie zależności, słabo udokumentowany kod, zależność od starego Pythona) doprowadziły do napisania następcy – **DNF** (*Dandified YUM*). Od **RHEL 8** menedżerem pakietów jest DNF, a polecenie `yum` zostało zachowane tylko dla zgodności.

### `yum` na RHEL 9/10 to dowiązanie do `dnf`

Sprawdź to sam:

```bash
# dokąd prowadzi plik /usr/bin/yum?
ls -l /usr/bin/yum
```

```text
lrwxrwxrwx. 1 root root 5 ... /usr/bin/yum -> dnf-3
```

`/usr/bin/yum` jest **dowiązaniem symbolicznym** (skrótem) do programu `dnf`. Cokolwiek wpiszesz po `yum`, wykona `dnf`. Dlatego:

- oba polecenia mają te same podpolecenia i opcje,
- oba czytają tę samą konfigurację (`/etc/dnf/dnf.conf`, `/etc/yum.repos.d/`),
- mają wspólną historię transakcji.

W tej lekcji przykłady piszemy z `yum`, żebyś oswoił się z tą nazwą. W kolejnych lekcjach przechodzimy na `dnf` – i tej formy używaj w nowych skryptach i notatkach.

> **Na Ubuntu/Debianie:** odpowiednikiem jest `apt` (dawniej `apt-get`). Porównanie poleceń znajdziesz w lekcji [6. Menedżery pakietów innych dystrybucji](6.%20Menedżery%20pakietów%20innych%20dystrybucji.md).

## W praktyce

Wszystkie polecenia, które **zmieniają** system (instalacja, usuwanie, aktualizacja), wymagają `sudo`. Polecenia, które tylko **pytają** (search, info, list), działają bez niego.

### Wyszukiwanie

```bash
# szukamy pakietów, których nazwa lub opis zawiera słowo „htop”
yum search htop
```

```text
=================== Nazwa dokładnie dopasowana: htop ===================
htop.x86_64 : Interactive process viewer
```

Jeśli szukanego programu nie ma, lista będzie pusta – wtedy warto sprawdzić, czy nie siedzi w dodatkowym repozytorium (np. EPEL, lekcja 3).

### Informacje o pakiecie

```bash
# opis, wersja, rozmiar, licencja – bez instalowania
yum info htop
```

```text
Dostępne pakiety
Nazwa         : htop
Wersja        : 3.2.2
Wydanie       : 1.el9
Architektura  : x86_64
Rozmiar       : 196 k
Źródło        : htop-3.2.2-1.el9.src.rpm
Repozytorium  : epel
Podsumowanie  : Interactive process viewer
Adres URL     : http://hisham.hm/htop/
Licencja      : GPLv2+
Opis          : htop is an interactive text-mode process viewer ...
```

W wierszu „Repozytorium” widzisz, skąd pakiet pochodzi. Pakiety już zainstalowane pokażą się w sekcji „Zainstalowane pakiety”.

### Instalacja i usuwanie

```bash
# instalacja; -y odpowiada „tak” na pytanie o potwierdzenie
sudo yum install -y htop

# usunięcie pakietu (pliki konfiguracyjne zmienione przez Ciebie zostają jako .rpmsave)
sudo yum remove htop
```

Można podać kilka pakietów naraz: `sudo yum install wget mc tree`.

### Aktualizacja

```bash
# co jest do zaktualizowania? (nic nie zmienia)
yum check-update

# aktualizacja wszystkiego
sudo yum update

# aktualizacja jednego pakietu
sudo yum update openssl
```

`yum check-update` kończy się kodem wyjścia 100, gdy są aktualizacje – to normalne, nie błąd. `yum update` i `yum upgrade` w DNF robią dokładnie to samo (w starym YUM różniły się obsługą pakietów przestarzałych).

### Co jest zainstalowane

```bash
# pełna lista zainstalowanych pakietów (długa – warto przefiltrować)
yum list installed

# tylko pakiety z „ssh” w nazwie
yum list installed | grep ssh
```

```text
libssh.x86_64                0.10.4-13.el9        @anaconda
openssh.x86_64               8.7p1-38.el9         @anaconda
openssh-clients.x86_64       8.7p1-38.el9         @anaconda
openssh-server.x86_64        8.7p1-38.el9         @anaconda
```

`@anaconda` oznacza: zainstalowane przez instalator systemu.

### Historia

Każda instalacja, usunięcie i aktualizacja to **transakcja** z numerem. Dzięki temu widzisz, co i kiedy się zmieniło, i możesz to cofnąć.

```bash
# lista transakcji, od najnowszej
yum history
```

```text
ID     | Wiersz poleceń           | Data i czas      | Działania   | Zmien.
-------------------------------------------------------------------------
     5 | install -y htop          | 2026-10-18 10:12 | Install     |    1
     4 | remove nginx             | 2026-10-18 09:58 | Removed     |    4
     3 | install nginx            | 2026-10-18 09:40 | Install     |    4
```

```bash
# szczegóły jednej transakcji
yum history info 3

# cofnięcie transakcji nr 5 (czyli usunięcie htop)
sudo yum history undo 5
```

Więcej o historii i cofaniu w lekcji [5. DNF – następca YUM](5.%20DNF%20–%20następca%20YUM.md).

## Najczęstsze błędy i pułapki

- **„Nie znaleziono dopasowania dla argumentu”** – literówka w nazwie albo pakiet jest w repozytorium, którego nie masz włączonego. Najpierw `yum search`, potem `yum install`.
- **Przerwanie `yum update` w połowie** (zamknięcie terminala, utrata sieci). System może zostać z pakietami w pół drogi. Nie panikuj: uruchom `sudo yum update` ponownie – DNF dokończy transakcję. Długie aktualizacje lepiej uruchamiać w `tmux`/`screen` albo lokalnie na konsoli.
- **`yum install plik.rpm` z katalogu bieżącego bez `./`** – `yum` pomyśli, że to nazwa pakietu z repozytorium. Pisz `sudo yum install ./plik.rpm`.
- **Automatyczne `-y` w skryptach bez zastanowienia.** `-y` potwierdza wszystko, także usunięcie 200 pakietów przy konflikcie zależności. W skryptach używaj go świadomie, a w terminalu czytaj podsumowanie.

## Podsumowanie

- `yum` to historyczna nazwa; na RHEL 8+ `/usr/bin/yum` jest dowiązaniem do `dnf`. Te same polecenia, ta sama konfiguracja.
- Pytania (`search`, `info`, `list`) bez `sudo`; zmiany (`install`, `remove`, `update`) z `sudo`.
- Każda zmiana to transakcja z numerem w `yum history` – da się ją cofnąć.

| Polecenie | Co robi |
|---|---|
| `yum search słowo` | szuka w nazwach i opisach pakietów |
| `yum info pakiet` | opis, wersja, repozytorium |
| `sudo yum install pakiet` | instaluje z zależnościami |
| `sudo yum remove pakiet` | usuwa pakiet |
| `yum check-update` | pokazuje dostępne aktualizacje |
| `sudo yum update` | aktualizuje wszystko (lub wskazany pakiet) |
| `yum list installed` | lista zainstalowanych |
| `yum history` | lista transakcji |
| `sudo yum history undo N` | cofa transakcję nr N |
